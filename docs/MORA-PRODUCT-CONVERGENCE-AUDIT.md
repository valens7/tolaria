## Delivery sequence and non-goals

1. **Mora Shell / Brand** — installable runtime becomes a recognizably Mora product with an OS Home and clean module entrances.
2. **Memos** — deliver the complete capture-to-recall P0 vertical slice on the frozen Vault / Shared Editor contracts.
3. **English Learning** — promote existing source-first work into the shell, complete real Read Aloud, and verify the source-to-review loop.
4. **Notes** — expose the existing workspace as a bounded module; no second workspace or storage system.
5. **Product-level OTA regression** — repeat N → N+1 only against the above product journey, checking the same Vault, same Memo path, same `memo_id`, and continued writing.

Not in this workstream: a new editor, a new database/storage architecture, a Vault migration, reimplementation of signing/updater, copying prototype state/code, or broad donor-feature expansion.

## Current verdict

The checked-in source now has a bounded **Mora Shell / Brand + Memos V1 Product Dogfood Candidate**. The installed `2026.9.602` runtime predates those source changes, so it remains a **Technical Dogfood** until this SHA is built, installed, and used by a human in the canonical journey. Mora is **not yet Mora Memos Daily-use Stable**: Human Dogfood, full experience review, minimal Review/Resurface, and product-level OTA regression are intentionally outstanding.
